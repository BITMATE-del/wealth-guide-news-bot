# 텔레그램 그룹 자동 동기화

기존 뉴스 봇과 별개로 동작하는 다중 사용자 계정 / 그룹 동기화 웹 서비스입니다. 기존 루트 뉴스 봇 및 GitHub Actions는 변경하지 않습니다.

## 사용 순서
1. Railway에서 **새 서비스**를 만들고 이 저장소를 선택한 다음 Root Directory를 `/telegram-sync`로 지정합니다. 기존 뉴스 봇 서비스와 분리합니다.
2. PostgreSQL을 연결하고 `DATABASE_URL`을 `postgresql+psycopg://...` 형태로 설정합니다.
3. `.env.example`의 환경변수를 Railway에 등록합니다. `TG_API_ID`/`TG_API_HASH`는 계정 소유자가 my.telegram.org에서 발급합니다. Fernet 키는 `python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"`로 생성합니다.
4. 연결된 웹 주소에 접속해 비밀번호로 로그인하고, 전화번호 인증 또는 본인의 Telethon `.session` 파일 업로드로 계정을 등록합니다.
5. 메인방, 감지 계정, 대상 그룹과 전송 방식을 선택합니다. **원본 작성자 계정**은 글 작성자와 동일한 Telegram 계정이 등록되어 있어야 작동합니다. **지정 계정**은 선택한 계정으로 전송합니다.

`.session` 파일은 Telethon SQLite 세션 형식만 지원합니다. Telegram Desktop의 `tdata`, Pyrogram의 세션 파일 등 형식이 다른 파일은 지원되지 않습니다. 이 경우 전화번호 인증 로그인을 이용하세요.

## 운영 유의사항
- 계정 세션은 암호화 저장되며 인증코드/2단계 비밀번호는 저장하지 않습니다. `.session` 파일은 로그인 권한이 있는 민감 정보입니다. 세션/비밀키를 Git이나 채팅으로 공유하지 마세요. 업로드 후 임시 파일은 제거하고 암호화된 세션만 저장합니다.
- Railway 인스턴스는 하나만 실행해야 중복 이벤트를 방지합니다.
- 그룹 참여 및 발언 권한이 필요합니다. 계정 소유자가 허가한 계정만 연결하세요.
- 현재 문자 메시지 및 일반 단일 미디어 메시지 복제를 지원합니다. 앨범, 답글 연결, 투표, 일부 특수 콘텐츠의 완전 복제는 아직 지원되지 않습니다.
- 관리자 로그인에 대한 IP 제한/레이트 리밋 및 별도 감사 기록은 공개 서비스 전 추가해야 합니다.
- **배포 및 실제 Telegram 계정 로그인/메시지 전송은 아직 검증되지 않았습니다.**
